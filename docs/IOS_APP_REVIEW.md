## iPad 実機が手元にない場合

今回の却下文から「開発者が iPad 実機で検証していなければ必ず不合格」とは判断できません。明示された提出物は、最新 OS の実機での画面収録と6項目への回答であり、iPad 個別の検証証明や動画は指定されていません。以下の iPad テスト項目は品質確認のための準備項目で、今回追加された提出必須書類ではありません。

一方、Apple の一般的な案内は、利用可能な各デバイスプラットフォームで実機テストするよう求めています。iPad の実機テストを省いても問題ないと保証するものではありません。手元の iPhone SE で実機テストと撮影を進め、iPad はまずシミュレーターで基本動作を確認する方針にできます。実機未検証を検証済みと記載せず、iPad 固有の不具合や追加依頼があればその内容に対応します。[Apple：互換端末でのテスト](https://developer.apple.com/help/app-review/before-submitting-for-review/test-compatible-devices)

iPad 向けの専用対応を外し、iPhone 向けのビルドに変更する選択肢はあります。Xcode の `TARGETED_DEVICE_FAMILY` を親アプリ・Safari 拡張とも `1`（iPhone）に設定し、新しいビルドを作成して差し替えます。現在の提出済み IPA は `[1, 2]` のため、審査メモや掲載画像を変更するだけでは対応端末は変わりません。初回公開前の変更として扱い、公開済みの iPad 対応アプリの更新では対応端末を削減できない制限にも注意します。[Apple：ビルド設定](https://developer.apple.com/documentation/xcode/build-settings-reference)、[対応端末の削減に関する説明（旧資料）](https://developer.apple.com/library/archive/qa/qa1623/_index.html)

ただし **iPhone 向けにしても、iPad での配信・審査から完全に除外できるとは限りません**。Apple は、iPhone 専用ハードウェアに依存しないアプリは iPad の互換モードでも利用可能で、Xcode の対応先から iPad を外しても iPad での配信可否は変わらないと説明しています。このアプリには、そのような専用ハードウェアへの依存は確認されません。配信を避ける目的で、実際には使わないハードウェアを必須条件に追加しません。[Apple：互換端末でのテストと配信条件](https://developer.apple.com/help/app-review/before-submitting-for-review/test-compatible-devices)

iPhone 向けビルドにすれば、iPad 専用の掲載画像を準備する負担は減らせますが、iPad 互換動作の確認まで不要とは判断できません。主動画は手元の iPhone SE で撮影できます。iPad の確認には、借用端末や iPad を持つテスターによる TestFlight テストを使う方法があります。シミュレーターでの基本確認も補助にします。現時点では、この資料に選択肢を追記した段階で、ビルド設定は変更していません。

## TestFlight から実機へインストールする

1. App Store Connect で、このアプリの **iOS** の審査対象バージョンと選択済みビルド番号を控えます。
2. TestFlight の「内部テスト」でグループを作成または選択し、対象ビルドを追加します。開発者自身の、対象アプリへアクセスできる App Store Connect ユーザーを内部テスターに選びます。別の人へ招待を送る場合は、送信先を事前に確定します。
3. 開発者の iPhone に TestFlight を入れ、内部テストへの参加を受け入れて対象ビルドをインストールします。複数ビルドがある場合は「以前のビルド」も確認し、審査対象と一致させます。
4. TestFlight 上のバージョン／ビルドを記録します。iPhone の「設定」→「一般」→「情報」等で実際の OS バージョンを控え、撮影時点の最新正式 OS であることをソフトウェアアップデート画面で確認します。
5. 以下の QA を行い、正常動作を確認してから撮影します。アプリを修正して新しいビルドを再提出する場合は、そのビルドで QA と撮影をやり直します。

内部テスターの設定方法は [Apple の手順](https://developer.apple.com/help/app-store-connect/test-a-beta-version/add-internal-testers)を参照してください。通常の提出用ビルドを内部グループへ追加できます。「TestFlight Internal Only」専用として新たにアップロードする必要はありません。

保存済み IPA も `1.0.0 (2494.16.15)` で、ユーザーが確認した提出ビルドの番号と一致します。親アプリ・拡張とも最低 iOS 16、対応端末は iPhone と iPad（`UIDeviceFamily: [1, 2]`）でした。現在のソースと Safari manifest は `1.1.0` なので、ソースのバージョンをそのままビルドのバージョンとして転記しないでください。既存資料にも異なるビルド番号の記載があります。

## 審査への登録

1. 審査担当者がサインインやアクセス申請なしで再生できる HTTPS の動画 URL を用意します。審査中に期限切れにならないようにし、サインアウト状態で再生できることを確認します。可能なら一般的な MP4 / H.264 で閲覧しやすくします（審査用動画の必須仕様という意味ではありません）。
2. [審査情報](../app/assets/app-store/審査情報.md)の iOS 向け Notes 案の `REPLACE_...` を実測結果で置き換えます。Notes は公式仕様で最大4000バイトなので、URL 等を入れた後も上限を確認します。[Apple：Notes の仕様](https://developer.apple.com/help/app-store-connect/reference/app-information/platform-version-information)
3. 6項目への回答を App Review Information の Notes に保存し、「サインインが必要」をオフにします。動画 URL は Notes の先頭に置きます。
4. App Review の返信にも、動画 URL と Notes を更新した旨を記載します。「Attach File」で資料を添付することもできますが、動画の添付可否・容量は実際の画面で確認します。添付だけに頼らず Notes に URL を残します。[Apple：審査メッセージへの返信](https://developer.apple.com/help/app-store-connect/manage-submissions-to-app-review/reply-to-app-review-messages/)
5. 掲載用スクリーンショットを実際の利用画面で補い、記載した手順と選択したビルドが一致していることを確認して再提出します。
