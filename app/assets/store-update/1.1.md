# Chrome / Edge / Firefox 1.1 更新提出

2026年10月31日作成。Chrome / Edge / Firefox の manifest は `1.1`、Safari と npm パッケージは対応する `1.1.0` に設定しています。
Safari は App Store Connect 上では `1.1` 登録済みです（2026年10月31日、ユーザー確認）。今回の署名・公証済み成果物 `20261030T161516Z-6124befa` は内部バージョン `1.0.0` のまま使用します。
次回はブラウザ版 `1.2` / Safari `1.2.0` に揃えます。[リリース管理メモ](../../../docs/RELEASING.md) を参照してください。

## アップロードするファイル

| 提出先                        | ファイル（`app/release/stores/1.1/` 内）   |
| ----------------------------- | ------------------------------------------ |
| Chrome Web Store              | `simple-web2md-ext-1.1-chrome.crx`         |
| Microsoft Edge Add-ons        | `simple-web2md-ext-1.1-chrome-edge.zip`    |
| Mozilla Add-ons：拡張本体     | `simple-web2md-ext-1.1-firefox.zip`        |
| Mozilla Add-ons：審査用ソース | `simple-web2md-ext-1.1-firefox-source.zip` |

この Chrome Web Store アイテムは **Verified CRX Uploads** により CRX での更新が必須です。登録済みの鍵で署名した上記 CRX を提出してください。ZIP を提出すると「アイテムを crx パッケージで更新する必要があります」と表示されます。
Edge / Mozilla には ZIP を提出します。ZIP 内のルートに `manifest.json` があります。
ソース ZIP は Mozilla のソースコード提出欄に指定します。本体 ZIP の代わりには使いません。
`SHA256SUMS` には 3 個の ZIP と Chrome 用 CRX のハッシュを記録しています。

## 各ストアでの操作

1. 既存アプリの管理画面を開き、新しいバージョンのパッケージとしてアップロードします。別のアプリを新規作成しないでください。
2. 更新前の版より `1.1` が大きいことを確認します。準備時に Chrome と Mozilla の公開版は `1.0` と確認しています。Edge の現在の版は Partner Center で確認してください。
3. パッケージの検証結果を確認し、更新内容と必要な審査メモを入力します。
4. 既存の掲載情報・プライバシー申告を確認し、各ストアで審査提出します。Mozilla には毎回、本体と一致するソース ZIP を添付します。

- Chrome：既存アイテムの Package から Upload New Package で CRX を指定し、その後 Submit for Review。
- Edge：Partner Center の既存拡張を開き、パッケージを差し替えて認定メモを入力し Publish。
- Mozilla：既存アドオンのバージョン管理から新バージョンを提出し、ソースコードありとしてソース ZIP を追加。

## 再生成

```sh
cd app
npm run package:stores
```

固定した依存関係を再インストールする場合は、先に `npm ci --no-audit` を実行します。
Chrome の既存ビルドは CRX も生成するため、従来どおり `.env` の `CHROME_EXTENSION_PEM` と Chrome 本体が必要です。
`package:stores` は CRX 内の全ファイルが Chrome ZIP と一致することを確認し、バージョン付きの CRX を提出フォルダーにコピーします。
審査用ソース ZIP のファイル配置・再現方法は [Mozilla のビルド説明](../../../docs/MOZILLA_REVIEW.md) を参照してください。
